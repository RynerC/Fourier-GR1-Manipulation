# GR1 姿态控制问题清单：哪些能用 Aurora SDK 解决

验证环境：GR-1P（gr1t2）Aurora SDK v1.2.1 镜像 + AuroraCore + MuJoCo 2.3.6（无界面仿真 `aurora_bridge/sim_server.py`），
客户端 `fourier_aurora_client 0.1.8`（经 `aurora_bridge/aurora_compat.py` 兼容）。所有数字都是仿真真值实测。

图例：✅ 用 Aurora 解决并验证　⚠️ 部分解决 / 有前提　❌ Aurora 解决不了

## A. 原项目（平面底盘 + 腿部动画）里的问题

| # | 问题 | 原来的做法 | Aurora 方案 | 状态与证据 |
|---|---|---|---|---|
| 1 | **倒着走**（导航策略经常倒退着走到桌边） | 底盘是全向速度执行器，前后对称、零滞后，倒着走没有代价 | 行走交给 LowerBodyCpgRLTask；导航按实测步态重新设计：几何“前进优先”跟踪器 + 在辨识模型上重训的 PPO（动作空间前进 0.45 / 后退仅 0.15，倒退每米扣 8 分） | ✅ 连续 6 个站位（Aurora 全物理）：旧策略 0/4 到达、倒退 18.3 m；新 PPO 6/6、平均误差 2.7 cm、17 s、倒退合计 0.29 m（单段最多 0.11 m，只出现在停靠修正）；几何跟踪器 6/6、8.2 cm、34 s。轨迹图 `docs/img/aurora_nav_compare.png` |
| 2 | 骨盆挂在滑动关节上，**没有平衡**；腿只是动画、不接触地面 | `base_x/base_y/base_yaw` 滑动关节 | FSM 3 走路（CPG+RL，真实足底接触）、FSM 2 PdStand 站立（全身模型平衡） | ✅ 0.12–0.45 m/s 前进、±0.5 rad/s 转向、横移都不摔；站立时承受 1 kg 手部负载 |
| 3 | 速度执行器理想化（立刻到速、想停就停） | `command_base()` 直接写速度 | 用 Aurora 实测响应：t63≈0.6 s（横移 1.5 s）、横移增益只有 45–65 %、死区 0.1、刹车滑行 0.08+0.43v、迈步时 +0.03 m/s 前向蠕动、直走偏航 −0.015 rad/s → 写成 `gait_model.py`，训练和控制器都按它设计 | ✅（这是“问题 1”的根因） |
| 4 | 够桌子靠**腰前倾 0.6 rad** + 底盘贴近 | IK 里腰 pitch 允许到 0.6 | PdStand 的站姿增量：Δz −0.08、Δpitch +0.2（整个人前俯，重心由全身控制器管）+ 腰 0.3 + 右臂前伸 | ✅ 手到身前 0.58 m、高 0.92 m，1 kg 负载下质心偏离双脚中点 <2.1 cm、漂移 0.01 m；完整抓放演示里 IK（右臂 7 关节 + 腰 yaw/pitch）闭环两次后末端误差 0.9–1.8 cm |
| 5 | 手臂开 **gravcomp**（重力补偿是“作弊”，真机电机要自己扛） | MuJoCo `gravcomp` | Aurora 上身 PD（kp 250/150/100…）+ PdStand 全身补偿 | ⚠️ 能扛住，但 1 kg 时手会下垂约 3 cm → 操作策略必须用视觉/末端位置闭环，不能假设关节指令=末端位置 |
| 6 | **端着物体走路**时手臂“焊死”在身上，没有动力学 | 腿动画 + 手臂关节目标 | 行走状态下上身切到“远程控制”（`set_upper_fsm_state(2)`），持续发端持姿态 | ✅ 贴身姿态 `ARM_TUCK`（手在身前 0.31 m）0.5 kg、`ARM_CARRY`（0.37 m）1 kg：走 0.3 m/s、转身、停、切回 PdStand 都稳定，横滚 ≤0.10 rad；抓放演示 3/3 端着物体绕桌走到另一侧，物体没掉、没摔 |
| 7 | 腰部既给 IK 用又要保持平衡 | 腰参与 IK | 行走时腰归行走策略（不能用）；操作时在 PdStand 里用腰 | ⚠️ 操作只在 PdStand 下进行；边走边伸手够东西做不到 |
| 8 | 操作时**底盘微调**（旧操作策略有 vx/vy/wz 输出） | 全向底盘 | PdStand 里不能挪脚，只能用站姿 Δyaw ±0.5 rad 转身 + 腰 yaw | ✅ 新操作环境 `sim/manip_aurora_env.py`：动作里的底盘换成站姿变化率 (Δz, Δpitch, Δyaw)；BC 策略在 Aurora 里 8/9（抓放 2/3、端持 3/3、放置 3/3），0 摔倒 |
| 9 | 关节模型不同 | GR1T1 + 灵巧手 | Aurora 只支持 gr1t2（GR-1P）；关节名相同，手腕 roll/pitch 范围不同 | ✅ 新操作环境直接用 SDK 里的 GR1T2 模型（`assets/gr1t2`），IK 与部署共用 `RightArmIK` |
| 10 | **定位**用仿真真值 | `base_pose()` 读 qpos | Aurora 的状态估计只给姿态可靠；位置靠腿式里程计，会漂（实测约 0.2 m） | ❌ 需要外部定位（视觉/激光 SLAM、动捕或看桌子做相对定位）。仿真里用 `true_data`（代替外部定位） |
| 11 | **灵巧手 / 抓取辅助** | 6 自由度手 + weld | GR1T2 的 Aurora 仿真模型没有手指；真机手由 `left_hand/right_hand` 控制组驱动，仿真无法验证 | ❌ 仿真里继续用 weld 抓取辅助 |

## B. 接入 Aurora 后新发现的姿态问题（都已解决，规则写在 `AuroraLoco` 里）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| B1 | PdStand 下一调站姿（哪怕 Δyaw 0.3）就**向前摔倒**；放吊绳时随机摔倒 | Default 零力矩时腰在重力下前倾 0.4–1.2 rad，PdStand 冻结了这个姿态，躯干前倾 0.45 rad；`isStanceState` 要求俯仰 ∈[−0.45, 0.6]、CoM 离双脚中点 <0.1 m，余量为零 → 进 Hanging 屈膝 → 摔 | 进 PdStand 后 2 s 内把腰回正（`set_group_cmd`）。JointStand 只使能腿（`motor_enable 0xFFF`），没用 |
| B2 | 进入行走那一下**冲出 5–14 cm**、甚至摔倒 | 躯干从前倾 0.4 rad 突然被行走策略拉直 + 吊绳半吊着时突然松开 | B1 + 慢放吊绳到双脚完全承重（`lower`）→ 冲击降到 1–2 cm |
| B3 | 站姿 Δz 一次给 −0.1 就摔 | 指令跳变 | 0.05 m/s、0.15 rad/s 斜坡；站姿为 0 时不持续发送 |
| B4 | 停车后还在动 | v1.2.1 速度指令无超时；停指令后 CPG 还会踏步数秒并前蹭 | 显式发 0；要精确停住就切 PdStand（立即停止踏步） |
| B5 | 小速度（≤0.1）没反应，机器人原地站着不走 | `updateCpgLocoState` 的死区（0.1，持续 1.5×步态周期才切 STAND） | 指令要么 0，要么 ≥0.12；停靠用定时小步 |
| B6 | 原地转向时往前蹭（0.12–0.14 m / 5 s），停靠时顶到桌子 | 迈步时整体 +0.03 m/s 前向偏置 | 原地转/横移时补偿 vx = −0.03（合速度≈0，不是倒着走） |
| B7 | 机器人收到两套指令、乱走摔倒 | 残留的 AuroraCore 和新的在同一 DDS 域（日志 “matched multiple publishers: 2”） | `stop_stack.sh` 清理所有 AuroraCore |
| B8 | CPU 不足时无故摔倒 | 行走任务单次 0.14–0.23 s（预算 0.02 s），仿真滞后 0.9 s | 实时性要求：至少 4 核，不和训练同时跑 |
| B10 | 第一次进入行走时机器人**直接瘫倒** | AuroraCore 每次进 FSM3 都重新加载行走策略 gr1t2_mix.pt；磁盘缓存为空时加载用了 2.7 s，期间腿没有控制器 | 还吊着时先进出一次 FSM3 预热（`startup(warmup=True)`），之后加载只要几十毫秒 |
| B11 | 预热之后放吊绳，偶尔**单腿着地摔倒** | 行走策略在空中踢过腿，PdStand 悬挂态要 3 s（`hanging_slerp_time`）才把双腿拉回对称；没等完就放，落地时一条腿伸直（膝 0.0）、一条弯着（膝 1.0） | 预热后至少等 3.5 s，并检查左右腿髋/膝/踝 pitch 相差 <0.08 rad 再放吊绳（`_legs_symmetric()`） |
| B12 | 走到桌边时**撞上桌沿被顶倒** | 停靠冲过头：台面 0.8 m 高，正好挡在躯干/前摆的手臂前；快速训练环境里撞桌只扣 0.5 分并被推开，策略没学到要留余量；仿真卡顿时刹车更晚 | 部署层加与策略无关的安全限速 `AuroraNavRunner.speed_guard()`：按正前方到桌子的距离限制前进速度，保证滑行（≈0.6·v）后身体前沿（骨盆前 0.15 m）碰不到桌子 |
| B13 | 刚开始走几秒就**侧摔**（某台 Windows/WSL2 机器上每次都摔，同一环境按单轴指令走不摔） | 起步时步态先往一侧晃一下（横向 0.4 m/s），导航策略看到偏离就同时给满横移 ±0.25 + 转向 ±0.7、横移方向来回翻转 → 左右晃动越来越大：横滚 0.13 → 0.27 rad、质心偏出双脚 0.22 m，约 9 s 侧摔。正常行走横滚 <0.04 rad | 部署层平衡保护 `AuroraNavRunner.balance_guard()`：横移 ≤0.15、转向 ≤0.5（实测稳定范围），转向 >0.3 时横移 ≤0.08，横移变化率 0.3 m/s²；机身横滚 >0.08 rad 时停横移、转向×0.3、前进 ≤0.2，等横滚 <0.04 持续 0.5 s 再恢复 |
| B14 | 操作验收时仿真**突然“快进”**、物体飞出几米、机器人摔倒 | sim_server 的抓取辅助每步把物体“摆”到手上（无限刚），物体再和手臂碰撞或被压进桌面 → MuJoCo 报 `QACC NaN` 并自动 `mj_resetData`（时间归零）→ 实时步进器以为落后了 100 多秒，全速追赶 | 抓着时物体不参与碰撞、高度夹在桌面/托盘之上；松手后先只和桌子/托盘碰，离手 >6 cm 再恢复和机器人的碰撞；检测到时间倒退就重新对齐时钟 |
| B15 | 端着物体放下时物体**歪倒** | 没有手指，物体刚性固定在手上；只控制末端位置时手腕姿态随 IK 漂，物体跟着歪 30–40° | IK 加“物体竖直轴保持竖直”约束（`RightArmIK.solve(up_axis=…)`，抓取那一刻记录）；快速环境与部署同一套 |
| B16 | 连续放 3 个物体时，前面放好的物体**凭空消失 / 被撞翻**，后面的放置失败 | ① 抓着的物体不碰撞，穿进托盘上已放好的物体，松手后恢复碰撞时重叠 → 弹飞；② 松手后只看“离手腕 >13 cm”就恢复和机器人的碰撞，物体还贴着前臂 → 弹飞；③ 端着物体只抬 8 cm 横移，撞倒 12 cm 高的邻居；④ 托盘 16 cm 太小，角上离边 1 cm；⑤ 选位置时够不着的角被排除后退回到已占的角 | 抓着时仍和桌子/托盘/其他物体碰；离开机器人所有碰撞体才恢复；漏斗式接近 + 安全高度平移；托盘 24 cm；选位置只选空角 |
| B9 | 头部指令在仿真里错位 | 官方 GR1T2 MJCF 的头部关节顺序是 yaw/roll/pitch，Aurora 是 roll/pitch/yaw | 本项目不发头部指令；要用头部需在 sim_server 里重排 |

## C. 推荐的 Aurora 使用流程（`AuroraLoco`）

```
吊着开机 → FSM2 PdStand → 腰回正(2 s) → 吊着进出一次 FSM3 预热 → 等双腿对称(≥3.5 s) → 慢放吊绳到完全承重 → 站稳 1 s
  ├─ 导航：walk_mode()：站姿回 0、等 1 s → FSM3 → 速度源 2 →（端持时上身远程 + ARM_TUCK）
  │        → 前进优先导航（或 PPO）→ 停靠 → stand_mode()：发 0 → FSM2 → 腰回正
  └─ 操作：stand_mode() 里：站姿 Δz/Δpitch/Δyaw 斜坡 + 上身关节斜坡 → 抓/放 → 站姿回 0
```
